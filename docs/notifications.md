# 自动选择通知

通知围绕已确认的自动切换、首选恢复回切、候选全部不可用和恢复可用记录事件，不额外测速。跟随公共出口的组不各自重复产生切换通知；记录直接发生自动选择的组。

## 开启与关闭

使用可信设备方式登录，在“设置 → 此设备的通知”点击“开启此设备通知”，允许系统通知，再点击发送测试通知的图标确认本机实际出现提醒。页面可选择关注全部自动组或指定组，以及故障／劣化切换、恢复和全部不可用三类事件。默认隐藏锁屏上的节点名称，需要时主动开启。

临时登录可查看最近事件，开启后台推送需要可信设备授权。通知设置按当前浏览器／主屏幕 Web App 保存；另一台设备须单独订阅。关闭通知保留管理登录；关闭页面保留订阅；短期管理会话自然到期不取消仍有效的可信设备订阅。主动退出、撤销设备或设备授权到期后停止新发送。已经交给推送服务的通知仍可能到达。

页面显示“推送服务已接受”只表示服务接收了请求，不证明操作系统已显示提醒。设置页可见时每 15 秒更新事件，也可主动刷新。最近事件保留在服务端，重新打开页面可读；系统通知不替代事件历史。

## 设备与浏览器条件

| 设备 | 本项目的适配入口 | 使用条件与限制 |
| --- | --- | --- |
| Windows | 支持 Push API 的 Edge／Chrome | 允许网站及系统通知；浏览器完全退出、后台设置和勿扰模式可能影响送达 |
| iPad／iPhone | iPadOS／iOS 16.4 及以上的主屏幕 Web App | 先“添加到主屏幕”，从图标打开，再点击开启通知；普通浏览器标签页会提示安装 |
| Android | 支持 Push API 的 Chrome 等浏览器 | 实际推送通道须可达；系统省电、强制停止、通知权限及浏览器实现会影响接收 |
| Linux 桌面 | 支持 Push API 的 Chrome／Chromium／Firefox 等 | 须有桌面通知服务；浏览器后台运行及发行版差异需在目标设备实测 |

系统名称只用于说明，是否允许开启由安全上下文、Notification、Service Worker、PushManager 等实际能力共同判断。设备兼容条件不代表每个平台都已经完成真机验收。

Apple 的主屏幕和用户操作要求见 [WebKit 官方说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)；标准推送机制见 [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API) 和 [Google Web Push 说明](https://web.dev/articles/push-notifications-overview)。

## 部署前提

管理页面须使用终端信任的 HTTPS 证书；忽略证书警告不等于满足推送条件。仅本机精确 loopback 可用 HTTP 做开发验证，局域网 IP 的普通 HTTP 不支持此功能。当前管理站点按根路径部署，清单及通知 Worker 分别位于 `/manifest.webmanifest` 和 `/cocoproxy-sw.js`，作用域为 `/`。

服务端通过出站 HTTPS 联系浏览器提供的推送服务，不要求把管理后台暴露到公网。当前仅接受 Google FCM、Mozilla、Apple 和 Windows 已知推送服务域名，并拒绝解析到私网的地址。服务端和终端都须能访问各自的推送基础设施；没有可用出站网络时无法保证即时提醒。手机离开内网仍可能收到系统通知，点击后打开后台则仍需能访问管理内网。

VAPID 密钥和订阅只在设备主动开启后写入私有状态。推送联系 URI 使用已配置的管理 HTTPS origin；服务端安装包必须包含锁文件固定的 `web-push` 及其完整生产依赖，缺失时显示组件不可用。首次启用无需额外账户或 Apple 开发者会员。

Worker 只处理通知及订阅更新，没有页面或 API 的离线缓存。通知点击只打开同源设置页，不接受载荷指定的外部链接。通知订阅异常、密钥变更或服务端订阅已失效时，重新打开设置页并修复订阅。更新 Worker 后若提示尚未生效，关闭该后台所有窗口，再重新打开。

## 合并与故障行为

同一设备、同一组的待发变化等待 10 秒，并合并为最新状态，避免连续故障与回切刷屏。发送最多两个并行，消息有效期 5 分钟，短暂网络错误和服务限流按退避重试；超过时效的历史不会恢复后逐条弹出。404／410 停用失效订阅，认证／配置错误显示在设备状态中。推送及通知存储故障不阻塞代理切换。

服务端保存最近 200 条事件，网页读取最近 100 条；待发队列、阶段状态和已处理事件跨管理服务重启保留。更换管理员凭据或管理 origin 会使旧设备与通知绑定失效，需要重新登录并开启。仍只支持单实例管理服务。

## 验证范围

`npm run test:notifications` 检查认证、CSRF、订阅校验、隐私、合并、重启、退避、失效、撤销和事件偏好。安装锁文件固定的运行依赖后，同时验证真实 RFC 8291 加密／解密与 VAPID 签名；缺依赖时该项明确跳过。

`npm run test:notifications-browser` 需要显式提供 `COCOPROXY_TEST_UI`（生成后的 UI public 目录）、`COCOPROXY_TEST_PLAYWRIGHT` 和 `COCOPROXY_TEST_BROWSER` 的绝对路径。它使用临时合成账户、真实网页和 Service Worker，仅模拟远端订阅与发送，不安装浏览器，不证明 FCM／APNs 实际送达或真机锁屏显示。真实系统通知仍须在部署后用各设备测试按钮验证。
