# CoCoProxy 1.0.0 正式发行

这是具有固定版本、组件锁和可安装载荷的正式发行，供符合条件的设备部署及真实使用。版本号不代替尚未完成的验收，实际支持范围与限制以本文为准。软件安装包与整机固件是不同交付形式；本版交付 Linux 软件，路由器组件由所选适配器另行提供，无须为 CoCoProxy 一律刷机。

## 本版内容

- 独立的 CoCoProxy 管理服务和 MetaCubeXD 网页，带管理员登录、订阅/节点/策略管理；选择后自动生效并核对核心出口，规则保存即生效。订阅卡片保持一个当前来源，延迟测试显示毫秒数或明确失败状态；管理员凭据来自部署输入，不写入源码，密码支持 10–1024 个 UTF-8 字节。
- 固定 Mihomo v1.19.33 原生 TUN、自动路由与重定向，必要的独立 guard、标记出口和终端回程集成。
- 显式启用的持久运行：早期 guard、已提交配置的串行恢复、实际 LAN 就绪等待、自有缺失资源重建，以及共锁维护暂停；协作路由器须同时具备相应启动／重连恢复能力。
- 具有清单摘要及文件白名单的 Linux 载荷，包含对应架构核心、构建后的管理服务及所需运行文件，不含真实订阅、节点、管理员凭据或证书私钥。
- 离线安装/升级/保留数据卸载入口，默认只读核验，显式 `--apply` 写入；HTTPS 反代及证书使用独立配置样本。
- [独立部署](deployment.md)、[HTTPS 网页](management-https.md)及[协同路由器要求与说明](support-matrix.md)，按角色说明路由器能力、两端配置与验收要求。

具体来源提交、核心/管理组件版本、依赖及每件文件的大小和 SHA-256 以该载荷的 `manifest.json` 为准，包外发布清单记录压缩包及 manifest 摘要。相同产品版本的不同架构必须按 manifest 区分，不能只按文件名选择。

## 支持与验收范围

| 项目 | 本版范围 |
| --- | --- |
| 外设 | Linux/systemd，固定审核的 ARM64 或 x86-64 核心，满足部署前置条件。ARM64 已有实机安装/升级、管理和代理证据；x86-64 仍须目标运行验收 |
| 路由器 | 满足来源选择、原始来源、DNS、回程、IPv6及故障/关闭要求的实现；已有实机证据来自一个可选适配器组合，不代表所有原厂或 OpenWrt 固件已适配 |
| 终端 | 精确同子网 LAN 的普通 IPv4 客户端，动态加入和 DHCP 地址变化由范围覆盖；旧单终端配置保持原范围，须显式关闭后迁移。受管公网 IPv6 阻断，不是双栈代理 |
| 已验证路径 | 真实手机代理/普通站点、核心停止阻断、路由器独立关闭恢复直连，以及手机管理登录；多源真实核心隔离验证覆盖双客户端 TCP/UDP、新加入地址、回程经过路由器、DNS 和核心停止阻断。隔离验证不代替多台实体终端验收 |
| 安装与运行 | ARM64公开安装入口已完成实机安装及升级；卸载生命周期另有隔离验证。服务启用和重启须由操作者按现场授权单独执行 |

## 已知限制

1. **早期保护须两端正确安装和启用。** 外设使用 network-pre 前的独立 guard unit；AlwayRoute 使用 fw4 ruleset-pre 的持久 guard，并在恢复条件满足后受控放行。目标网络管理器启动顺序、fw4 自动 include、实际冷启动全过程及物理拔插须对具体组合验收。任意 firewall stop／全表 flush 仍无连续阻断保证，不等同正常 reload。
2. 持久运行默认未启用，须按总指南完成参数持久化及显式 enable。代码与隔离网络验证不代替整机断电、物理换口、多终端或持续负载；尚未实测的项目继续标为待验收，不能把一次运行成功视为长期稳定性承诺。
3. LAN 模式须两端一致配置精确接入子网，并保留独立回程表；不能仅放宽一端来源字段。多台实体终端并发和长期使用仍需现场验收。跨网段、终端直接把外设作为 DHCP 网关、桥接、VPN 入口及完整 IPv6 代理尚未交付。
4. 路由器应用的 DNS 预检只证明局部可达，CoCoProxy 核心就绪也不替代终端路径验收。应用失败及未知资源仍按实际错误显示，不自动删除未知系统配置。
5. 自签名 HTTPS 首次访问需操作者确认本地证书。节点可解析与节点可联网分别验证，不保证任意订阅中的全部节点均可用。

部署参数、界面登录方式及关闭恢复入口应在现场私有操作说明中提供。升级前先暂停外设持久恢复，成功返回后从协同路由器关闭交付；按安装器的维护流程停止服务、退役自有网络，再升级并验证。发行包不包含个人环境恢复材料，也不自动更改其他设备或执行整机重启。
