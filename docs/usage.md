# 使用说明

本文适用于已完成[部署](deployment.md)并可访问 HTTPS 管理入口的实例。当前支持范围与限制见[发行说明](release-notes.md)；路由器负责流量交付和关闭，Coproxy 网页负责订阅、策略及核心配置。

## 登录与导入订阅

1. 打开部署者提供的 HTTPS 地址，用部署时设置的管理员账户登录。自签名证书首次访问应通过可信方式核对指纹。
2. 进入“订阅”，选择“导入订阅”，填写名称和地址。新增后会尝试更新；保存地址成功与更新成功分别显示。
3. 检查节点数量、更新时间和错误。修改已有来源时，地址留空会保留原地址。

接受 JSON／Clash YAML 节点或支持的完整配置，不支持 URI/base64 转换。完整配置中的监听、DNS、TUN 等部署字段会被剥离；不支持的规则或 provider 形式会报错。下载来源须在部署许可内，HTTP 来源需要单独许可；无法下载时由部署者核对许可和连通性，不要把订阅地址公开到日志或截图。

刷新失败时，地址未变可继续使用上次成功快照；更换地址后需重新成功更新。来源刷新不会自动替换正在运行的配置。

## 选择方案与运行模式

顶部“配置方案”决定如何使用来源：

| 方案 | 使用方式 |
| --- | --- |
| 本地规则模板 | 可选多个订阅的节点，使用内置业务分类、国内补漏和自定义规则 |
| 订阅配置 | 选一份标为“配置”的来源，保留其策略组和规则，单独保存你的选择与覆盖 |
| 现有配置 | 旧草稿兼容状态，在明确保存或切换前保留原配置；不是可新选的第三种方案 |

在订阅卡片点“选用”：本地模板中切换该来源是否加入，订阅配置中选它作为基础。两套方案的用户选择和规则分别保存，切换后仍需应用。

“运行模式”可选规则、全局或直连。全局／直连绕过业务规则，分别将业务交给统一代理出口或 DIRECT。**直连模式仍由 Coproxy 处理交付流量；完全关闭交付应从路由器操作。**

## 保存与应用

方案、来源选择和策略组下拉修改会保存设置；自定义规则可点“保存”，或直接点“应用”先保存再应用。出现“待应用”表示运行配置尚未与当前编辑一致。

点“应用”后，服务会校验配置并切换核心，失败时保留或尝试恢复上一确认配置。应用成功只说明配置和核心确认通过，终端代理连通仍需实际访问验证。“刷新”工具栏只重读页面状态；订阅卡片的更新操作才会下载来源。

多人或多个页面同时编辑发生冲突时，刷新并核对最新设置后重做操作，避免连续重复提交。旧配置迁移会尽量保留实际手动出口；核心离线时仍可保存可修复设置。

## 节点与规则

“代理”的“策略组”可修改手动选择组。自动组由核心算法选择，不能在该下拉中手动覆盖。本地模板可添加业务组或自定义组；删除组前先移除引用它的规则。“节点”用于查看核心节点状态；延迟探测地址由部署许可控制。

“规则”的“自定义规则”支持添加、编辑、排序及删除，按列表顺序优先匹配。规则只覆盖当前方案；订阅原规则和模板规则仍由各自来源维护。“生效规则”读取当前核心，保存后尚未应用的编辑不会立即出现在其中。

节点或策略组更名、来源更新后，旧选择可能失效。页面提供“重置失效选择”时可先重置，再核对目标并应用；也可恢复来源或修改引用规则。

## 删除、离线与关闭

删除订阅前，页面会解除工作区对该来源的选用；若它是基础订阅，会切回本地模板。删除不会直接清除已生成的运行候选，按提示核对剩余节点和规则后应用。

核心离线时网页仍可用于编辑。核心状态、连接或生效规则可能显示不可用；先查看设置页错误，再由部署者处理运行故障，恢复后重试加载。应用恢复失败时不要绕过事务裸启动核心，维护方法见[运行模块](../packages/runtime/README.md)。

要恢复普通直连，在协同路由器自己的管理入口关闭交付。仅停止核心会保留独立 guard，并继续阻断受管外网。外设离线时路由器也应能独立关闭；维护升级前同样先关闭交付。管理服务重启会使登录会话失效，操作完成后可主动退出。
