# 与接入路由器的协作

状态：协作语义 v1，2026-10-25；尚无已完成的跨设备接口或联合验收。本文说明 Coproxy 的责任和外部依赖，不记录个人设备、真实网络拓扑或路由器内部控制实现。

## 1. 通用协作要求与本机联调资料

本文保存 Coproxy 侧的通用协作要求。最小语义与 AlwayRoute `contracts/external-v1.md` 对齐；字段和实现属于各自项目，不以本文代替本机联调记录或其他项目的变更授权。

当前网络拓扑、真实设备与地址、接线、访问方法、调试输出和环境专用脚本属于本机资料。共同资料维护在双方仓库之外的一份共享目录中，各项目通过被忽略的目录链接 `.local/lab/shared/` 直接读取共享目录的导航和环境文件。真实路径不进入正式文件，项目独有资料继续留在自己的 `.local/`。

目录链接只提供资料入口，不会自动迁移旧内容、运行脚本或替换现有工具配置。链接缺失、失效或共同环境信息未核验时应明确提示，不猜测替代。

路由器模式切换与回退的内部机制不在本仓库记录。既有路由器管理 RPC 和上游核心 API 均不能自动视为跨项目接口已经存在。

联调前应确认必要的接口含义，记录双方明确的源码提交、组件版本及验收范围，不依赖两个分支的最新版恰好兼容。实际环境与原始记录保持私有；文档或提交只在本地存在时，不把它描述成远程已发布。

## 2. 职责与逻辑路径

| 角色 | 责任 |
| --- | --- |
| 接入路由器 | 终端接入、基础网络、受管终端范围、把流量交给网关和独立管理入口 |
| Coproxy 网关 | 收到流量后的透明接管、DNS 与分流、节点及订阅、代理出口连接和自身状态 |
| 上级网络 | 为经许可的出站连接提供外部可达路径 |

逻辑流为：终端 → 接入路由器 → Coproxy → 经路由器出口访问上级网络。它是产品角色关系，实际接线、接口和地址由部署输入决定。

Coproxy 不直接写路由器 UCI，不以匿名健康检查触发设备动作，也不同时充当第二个路由器配置负责者。主机自身代理成功只能验证局部路径，不能替代终端接管验收。

## 3. Coproxy 需要满足的协作条件

- 接管方式与内核能力匹配，明确入口、受管来源、出口和排除范围；核心出站不再次被接管，数据与回程一起验证。一个网口也可承载不同阶段，但不能据此跳过连接跟踪和同接口路径检查。
- 优先维持终端网关和 DNS 入口的稳定性；网关接收路由器交付的解析请求，基础解析不得循环依赖该请求链。本地域名和管理访问不被破坏。
- TCP／UDP 和地址族分别声明支持范围；加密 DNS 和普通 DNS 分开评估，未知或未接管能力不伪报为支持。
- 区分服务就绪、配置应用、节点检查与终端实际出口；报告新鲜度和运行代次，不用过期快照确认新的配置。
- 管理身份、访问地址、接口和端口均为受控部署输入。原始凭据和实际环境数据不写入公共状态或版本契约。
- 网关只能确认自己的服务及检查结果，不能以自己停止或重启推导路由器已完成相应操作。双方部分完成时保持真实状态，故障边界须在共同约定确认后验证。

## 4. 联调和发布流程

1. 先确认通用职责、状态、兼容与验收要求；涉及运行环境的信息通过本地共享入口读取并核验，其他项目的代码、配置或设备变更仍需相应授权。
2. 各自完成对应模块与针对性检查；实际接入前确认路由器端已经具备所需管理和恢复能力，不能只因 Coproxy 就绪就扩大范围。
3. 只接入一台测试终端，按双方确认的联合清单验证协议、DNS、回程、故障和重启；具体路由器操作须在其项目范围内另行授权。
4. 正式结论只记录必要的脱敏条件、双方提交、组件版本及支持范围。仓库自身的原始材料按 AGENTS.md 放在 `.local/`；共同材料通过共享入口维护，不复制进正式文档或各自重复保存。
5. 在已验证组合上扩大终端范围；软件可独立升级，只有共同约定和能力要求变化时才需要另一端配套升级。未通过组合不宣称兼容。

实际测试入口、凭据与环境配置不跨仓库复制为正式内容；不要为联调建立必须依赖某台电脑目录的链接。本文与[项目方案](project-plan.md)共同定义 Coproxy 侧的工作范围，不代替对方项目作设计或实施决定。

## 5. 首轮共同语义 v1

- 范围为一台明确来源的终端、IPv4 TCP/UDP、真实地址 DNS；未支持的公网 IPv6 在受管范围阻断，本地控制与管理保留。终端默认网关和 DNS 入口仍为接入路由器。
- 路由器交付原终端源地址，Coproxy 确认受管来源和排除范围；新建出站连接经路由器 WAN，回程经路由器。网关自身出站不能再次被交付；同 LAN 的 MAC、回程、连接跟踪和原样转发防护须实测。端间不增加 SNAT 掩盖路径问题。
- 路由器分别配置链路接口、路由器/网关地址与网关 MAC、测试终端 IPv4/MAC、额外目的 CIDR 例外、网关 DNS 端口及专用 DNS 监听。本机实际值只留在本地资料；这些输入不是 Coproxy 自动修改路由器的接口。
- Coproxy 提供受限的 UDP/TCP DNS，网关 bootstrap 独立。路由器只把选中终端的公网解析送往该入口，本地域和无点名称保留基础解析，不切换所有终端共用上游。DoH/DoT 单独作为业务流量验证。
- 故障策略已经确认：开启后核心、DNS 或链路故障时阻断受管外网流量，保留开启意图并提示异常；用户手动关闭后恢复普通直连，不自动降级。初次开启预检失败保持原状态。
- 分别报告保存版本、期望启用状态、应用版本、核心/接管/DNS 状态、配置代次、错误和观测时间；不混用路由器 revision 与网关 generation。就绪不能推导真实终端出口已经验收。
- 首轮采用人工检查及本地诊断，不要求新建跨设备控制 API。AlwayRoute 应用接收标记为 `operator` 的短期观察，匹配目标网关、请求 revision 和网关 generation，观察不超过 30 秒，并明确核心、接管、DNS、来源保留及出口/回程条件。重启后先恢复阻断，重新观察后再显式应用；过期观察不能作为新的应用确认。
- Coproxy 当前显式代理编译及离线事务模块不满足上述网关条件；未交付的状态和接管能力继续如实标记，不使用测试替身向路由器伪报就绪。

兼容性以当次双方提交、安装版本及验收范围确认；语义 v1 对齐不表示已经部署、通过联合验收或所有后端字段已经由 Coproxy 实现。
