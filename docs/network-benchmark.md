# Windows 多站点网络压测

使用现有 Node.js ≥22.18 和 curl ≥8.4，不需要 npm、Windows Python 或管理员权限。电脑作为真实终端，流量按当前系统路由和透明网关规则发送；脚本不会切换 Wi-Fi、代理节点、策略组或外接代理开关。操作期间无需 Agent 在线。

## 一键运行

1. 连接要测的网络，固定位置、频段和节点，暂停其他下载及重型构建。
2. 双击仓库根目录 `run-network-benchmark.cmd`，填写本轮场景名称，回车开始。
3. 等待约 2～4 分钟，实际时长取决于通过能力检查的站点、失败超时与流量预算。窗口会显示当前阶段和结果目录。
4. 默认结果位于 `.local/reports/network-benchmark/<本次目录>/`。先看 `summary.txt`；分析时提供 `report.json`、`samples.jsonl` 和存在的 `path-evidence.jsonl`。`summary.csv` 可用表格软件查看。

场景名称只用于记录，不证明流量经过何处。要比较外接代理关闭与开启后的直连处理开销，需要手动切换相应状态、分别运行；不要混同为代理节点性能对比。

## 默认站点与测量方法

| 分组 | 常用站点 | 默认用途 |
| --- | --- | --- |
| 国内 | 百度、腾讯、哔哩哔哩、网易 | 空闲及负载期间的访问时延、成功率 |
| 国外 | Google、GitHub、YouTube、Wikipedia | 空闲及负载期间的访问时延、成功率 |
| 公开下载资源 | 微信安装包、哔哩哔哩安装包、Google Platform Tools | 能力检查通过后，固定窗口的单连接及少量并发下载 |
| 补充专用服务 | Cloudflare | 独立检查、独立跳过的下载及上传，不是整轮测试的前提 |

公开资源来源：[微信官方页面](https://pc.weixin.qq.com/)、[哔哩哔哩官方下载中心](https://app.bilibili.com/)、[Android Platform Tools 官方页面](https://developer.android.com/tools/releases/platform-tools)、[Cloudflare Speedtest](https://github.com/cloudflare/speedtest)。脚本只下载并丢弃数据，不安装这些软件。网站和文件 URL 会变化，失效时应在私有配置更新；不通过伪造 Host、修改 SNI、忽略证书或绕过访问控制强行测速。

先逐站做小量下载／上传能力检查。普通文件下载要求 Range 请求、HTTP 206、正确 Content-Range、精确正文长度和二进制类型，检查量为 64 KiB；HTML、错误页、重定向、失效文件及不支持 Range 的源会明确跳过。Cloudflare 使用其专用 `bytes` 参数，与普通网站协议分开。

随后采集 15 秒空闲基线。每个可用下载源分别进行最多 15 秒单连接和最多 15 秒双连接下载；各负载阶段同时对全部常用站点每约 4 秒发起一个 GET，观察访问表现。慢请求完成后才继续同站探测；各站错开启动，阶段结束后停止新探测、等待已开始请求结束。阶段间休息 2 秒。

优先用至少两个在候选阶段所有负载连接都通过 DIRECT 关联的源，进行多站点同时下载。若证据不足但至少两个国内下载源可用，仍测“当前路由多站点聚合”，不把它命名为已验证直连。正式阶段重新核对连接；之前的证据不等于后续路径保证。结果保存实际 DIRECT、代理、混合、部分验证或未知分类及覆盖率；只有整个阶段均已验证直连且选择稳定时，`verifiedDirectMbps` 才有值，否则为 null。`observedDirectPayloadMbps` 仅累计被捕获为 DIRECT 的下载字节，是已观测部分，不能当作整阶段带宽。

只有专门提供上传能力的服务才接收 POST，普通网站首页不用于上传压测。没有有效上传服务时只跳过上传，继续其他测量，不捏造“多个网站上传”能力。默认上传只有一个补充端点，不能据此得出独立于服务端限制的上行极限。

## 路径证据

可通过私有配置启用已有 SSH 管理通道上的只读连接观察。远端使用已有 Python 读取既有运行配置及凭据位置，只 GET Mihomo `/proxies` 和 `/connections`，不会复制密钥、开放端口、部署远端文件或修改选择。

观察仅输出指定本机源 IP、指定测试主机的连接，其他终端或其他网站记录不保存。连接 ID、节点名、规则和选择值以摘要记录；凭据不回传。使用 curl 的源 IP／端口、目标端口、域名或 IP、本机请求时间窗关联运行时记录，再解析实际出站链类型。组名、静态规则、远端 IP或手工标签本身均不能通过验证。

观察周期约 1 秒，短连接可能无法捕获；源地址被改写、连接无法唯一匹配、组选择变化、SSH 不可用时明确记为未验证或歧义，不自动认定直连。缺少证据的成绩可用于描述当前路由下的业务表现，但不能记入已验证直连上限。远端观察有独立时限，结束 stdin 会退出；不依赖 Agent 保持在线。

默认读取存在的 `.local/environments/network-benchmark.json`，也可显式 `--config`。可只配置观察器并沿用内置目标：

```json
{
  "schemaVersion": 1,
  "observer": {
    "sshHost": "reviewed-gateway-alias",
    "runtimeSettingsPath": "/absolute/private/runtime.json"
  }
}
```

这是合成示例，真实 SSH 别名、设备路径和结果只保存在 `.local/`。如需替换目标，配置中增加 `targets` 数组，每项包括 `id`、`name`、`region`（domestic/overseas/custom）、`probeUrl`；可选 `download: {"mode":"range","url":"https://download.example/file.bin"}` 或专门支持 `bytes` 参数的下载接口，可选 `uploadUrl`。每个站点的能力和失败独立处理。

## 流量、停止与参数

默认整轮负载有效载荷预算为 2048 MiB，各负载阶段及 worker 预留公平份额，避免第一个快站耗尽预算而其他站点无法测试，也不让一个 worker 独占并发阶段。达到阶段份额会提前结束，结果保留实际持续时间、已启动 worker／站点数及原因。下载有客户端大小限制，实际超额会如实记账并停止后续负载。小量预检、网页探测、TLS/协议开销不包含在这个负载预算内；它不是网卡层的严格总流量上限。满载仍会影响同链路聊天或其他业务。

```powershell
# 更充分的时延样本和重复对照，并增加负载预算。
node scripts/network-benchmark.mjs --label same-network --duration-seconds 45 --idle-seconds 45 --rounds 3 --max-mib 8192

# 查看参数，不联网。
node scripts/network-benchmark.mjs --help
```

按 Ctrl+C 会停止负载子进程、关闭观察器并尽量保存数据。逐请求记录持续落盘，各阶段完成后更新报告；强制关闭窗口或杀进程不保证最终摘要完成。每个请求有独立截止时间和进程看门狗，不永久重试。某站请求连续失败两次，其负载 worker 提前退出；不阻止其他站点。

## 如何解释结果

- 吞吐是有效 HTTP 文件载荷除以实际负载窗口，包含建连与请求间隙，是业务下载吞吐。下载响应语义正确、完成或阶段截止时已有有效传输，才计入数据；没有建立连接的截止超时仍是失败，不能当作正常截断隐藏。
- 首页和小资源测的是冷连接 TTFB、请求总时间及成功率，包含 DNS、TCP、TLS、网络和服务端时间；不等于 ping RTT、纯排队时延或 UDP 丢包率。各站分别输出空闲和负载数据、相对空闲的 p50 增量，不跨网站混平均。
- 每个在阶段内开始的探测都计入尝试数。跨阶段的失败仍保留；晚到成功样本单列为跨界样本，不用它提高阶段内成功率，也不塞入阶段内时延分布。记录探测是否与实际有传输的请求重叠，没有有效负载时不能称为满载时延。
- 低样本量的 P95 仅供探索；默认不输出 P99。阶段提前因预算结束、站点失败、核心选择变化等都会影响解释，须结合 JSON 原始记录。
- 上传速率是客户端发送量，`successfulPostClientBytes` 只表示成功结束 POST 的客户端发送量；除非服务端实际报告接收计数，不能叫服务端确认吞吐。
- 多站点可帮助发现单站限速或拥挤，不能消除所有远端因素。即使多个站点都跑不高，也不能直接断言就是设备极限；无线接入、共享上游、服务端和当前分流路径仍可能限制结果。代理路径单列，不混入直连带宽结论。
- 结果含真实接口、默认路由、连接地址及目标，全部留在被忽略的本地目录，不公开、不提交。不采集网站正文、原始 curl 错误、订阅和凭据。

针对性本机合成验证：`node --test tests/network-benchmark.test.mjs tests/benchmark-observer.test.mjs`。远端 Python 纯函数及生命周期用既有 Python 配合 `COPROXY_TEST_PYTHON` 显式启用；不安装运行时，不运行互联网满载测试。
