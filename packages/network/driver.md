# 固定生产网关驱动组合

`GatewayNetworkDriver.production(settings)` 固定组合主机预检、持久原生资源会话、核心监管、管理服务 PID 来源及运行证据。生产入口要求 Linux root，没有 backend 参数、依赖注入或失败后的 fixture 回退。构造不创建目录或安装服务；实际执行前各组件重新核验自己的工具、权限、配置和资源来源。

调用 `driver.coordinator()` 取得唯一 `NetworkCoordinator`，通过它的 revision CAS、启动恢复门闩及逐操作持久屏障执行。驱动方法是可信进程内接口，不应直接暴露给网页、CLI JSON 或第二个写入者。生产 helper 的认证入口、部署以及持续故障观察仍须接入；导入该模块不会自动启用网关。

## 部署输入与归属

`GatewayDriverSettings` 显式提供四个独立目录：协调器 authority、原生资源 authority、核心 runtime state 和 coreHome。目录必须为规范绝对 POSIX 路径，彼此不能相同或互为祖先，锁顺序固定为协调器 → 单个组件；不能把多份 authority 指向同一网络域来规避唯一写入者。

核心设置必须完全等于重新生成的 [runtime plan](runtime-plan.md)，包括固定 unit 摘要。网络计划重新渲染并匹配完整 SHA、核心 UID、binary/unit SHA，且强制独立管理 UID。原生会话、主机观察、DNS/TUN 探针与链路观察使用同一受信 ip 工具；其他工具只接受对应固定名称及系统路径。

DNS 探针域名、期望 IPv4 和路由查询目的地由受保护部署设置提供，不能由浏览器临时指定。域名应有覆盖随机子域名的真实记录；DNS 单传输使用组件固定默认期限。路由查询目的地必须为部署网段与保留 TUN /15 之外的单播地址，不能用入口网段路由代替实际出口事实。所有真实地址、配置、凭据与输出继续保存在私有区域。

## 应用与恢复

应用顺序为：

1. 只读核验资源、旧核心操作收敛、完整候选及主机条件。
2. 协调器写入启用意图和操作屏障，驱动安装并回读 blocked。已有资源凭据使用旧计划精确打开并恢复；同保护参数的新配置代次先撤回 capture、保持 blocked，再显式 rebind。
3. 保留黑洞与撤回 capture，准备固定资源；独立证明 blocked 后，由唯一核心监管器执行 stop、选择候选和 start。
4. 从固定管理 systemd 单元取得 PID，结合完整核心与两个 cgroup、socket 来源观察核验同一身份，再重新检查主机并开放 core-only。
5. 执行实际 DNS/TUN、链路、socket 与资源观察；激活前再次取得完整 core-only 证据，之后增加 capture 并切换 active。
6. 以 active 模式重新读取全部证据后，协调器才保存 ready。它只声明本机就绪，终端路径仍为 unverified。

管理 PID 不能由调用者自报。固定服务观察与完整身份之间必须匹配 boot ID、PID、启动时间及独立管理 UID；替换进程不能继承旧授权。身份比较忽略观察时间，但保留所有核心、管理及计划字段，证据最多 30 秒。

显式恢复先进行不依赖候选的 provenance 观察，协调器持久保存 settling，再分别收敛原生 worker 与核心旧操作，随后独立证明两者均已结束。此后完整核对资源归属，恢复 blocked、保留黑洞并停止核心；不会重新激活。恢复阻断不以主机旁路检查或待应用候选可读为前提，避免就绪条件失效反而阻止恢复。恢复只使用已核验资源及固定受信工具，仍拒绝未知归属。

成功恢复后必须显式重新 apply。未知变更异常会丢弃缓存会话并保留未收敛屏障，不能直接重试或并发补写；已证明工具收敛的就绪失败才进入协调器的阻断与核心停止路径。驱动本身不操作路由器，不提供关闭后恢复直连或自动 DIRECT 回退。

## 验证与剩余边界

`test:network-driver` 使用明确 fixture 核心／资源／观察依赖，测试完整组合顺序、同保护参数代次更新、管理身份替换、来源混用拒绝及失败屏障。Linux 子项使用真实协调器、文件、锁和持久 journal，核验每个组合变更前的 unsettled 屏障、未知激活失败后的直接重试拒绝、显式恢复只阻断，以及 active 证据失败后的撤回与核心停止。fixture 永远保持 fixture scope。

真实 nft／路由和 DNS/TUN 已有独立四角色隔离测试；上述组合测试没有同时运行真实 systemd、两个固定服务和完整生产 host 观察，不能合并推导为生产部署通过。生产 root 正向、helper 认证接口、管理端接入、持续故障处理、关闭生命周期和真实终端联合验收仍待完成。

当前驱动支持固定核心 binary/unit 下的配置代次迁移。不能直接替换 binary/unit 设置后用新驱动恢复旧 authority；核心 artifact 升级需要独立部署协议，先用旧配置完成安全收敛，并核验新部署。原生资源的跨 boot、namespace、工具二进制迁移也仍未支持。遇到这些域变化只拒绝，不能通过删除凭据或认领同名内核资源绕过。
