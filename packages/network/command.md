# 网络工具的有界命令传输

`runNetworkCommand(binary, args, options?)` 为后续固定网络执行者调用已审阅的 `ip`／`nft` 客户端提供传输。它不构造规则、不决定资源归属、不授予 root 权限，也没有管理 HTTP 或 shell 入口。调用方仍必须从可信安装配置取得可执行路径，核验所有权和祖先，并在目标操作已获授权后使用。

仅支持 Linux 和显式绝对可执行路径。参数单独传给进程，不经过 shell；最多 64 个参数，每个最多 16 KiB，拒绝控制字符。`options.input` 提供完整标准输入，例如一次 nft 批次，最多 256 KiB，拒绝 NUL。子进程只继承固定 PATH、LANG 和 LC_ALL，不继承代理、令牌或加载器环境。

默认超时 15 秒，允许明确缩短或延长至最多 60 秒。stdout 与 stderr 合计默认最多 1 MiB，调用方最多可设 4 MiB；stderr 不进入返回内容，stdout 要求严格 UTF-8。工具输出可能包含真实部署信息，返回字符串只能用于私有检查，不应直接转成公开日志或响应。异常只包含固定错误码，不附带工具原始诊断。

超时、输入管道失败或输出超限时先终止进程组，等待 SIGKILL 升级收敛后才返回。`NetworkCommandError.childSettled` 为 false 表示最终截止时仍未确认进程结束；调用方必须持久保留未知／故障状态和已有阻断，不能与尚未收敛的操作并行执行恢复变更。即使子进程已经退出，内核资源是否匹配仍须独立回读，不能把退出码当成网关就绪。

该机制针对不自行脱离进程组的可信系统工具，不是恶意程序沙箱。调用方还需实现持久事务、锁、代次 CAS、所有权检查、内核回读及故障策略。

`tests/network-command.test.ts` 使用真实 Node 子进程验证无 shell 的标准输入和参数传输、环境隔离、固定错误、输出限额、UTF-8，以及超时后的后代进程不能延迟写入状态。它不调用网络工具，不修改主机网络，也不证明尚未安装的特权执行者已经可用。
